## Use ASD-STE100 Simplified Technical English

Write comments in simplified technical English.

Key rules:

- Use the approved words of ASD-STE100 when possible.
- Use one word for one idea. Do not use two words for the same thing.
- Write short sentences. Use 20 words or less for instructions.
- Use active voice. Write "Turn the switch", not "The switch must be turned"
- Write short paragraphs. Keep one topic in each paragraph.
- No filler.

The goal is easy reading.

Report back to the user following the same rules.

## Brief comments — no archaeology

Comments state the live invariant in ≤1 line. The reader needs current behavior, nothing more.

- Banned content: bug postmortems, "we tried X but Y broke", "previously", "used to", "added because of", historical justification, restoration sagas.
- Test: "If I delete this comment, will a reader misunderstand the code?" No → delete. Yes → minimum text, present tense.
- Decision rationale and bug-fix narration go in the commit message that introduced the change.
- Use `TODO:` only for concrete, actionable follow-ups.

## Consistency guardrails

- Keep one source of truth for each content concept: one file per definition, one package per saga, one directory per instance.
- `src/schema/runtime-contract.json` is generated by the engine (`node bin/cyberia stat-contract`). Never hand-edit it.
- `dist/` and `artifacts/` are build outputs. Never hand-edit them.
- Keep content JSON in canonical form. Run `node bin/cyberia-content.js validate --fix`.
- No dead code, legacy code or unused dependencies.

## Architecture boundaries

This repository creates content. The engine consumes it.

- `src/content/` owns the authored content: foundation, instances and sagas.
- `src/schema/` owns the definition schema and reads the runtime contract.
- `src/validation/` owns the content rules and the canonical form.
- `src/generator/` owns semantic generation: prompts, stages, the saga package and the Gemini client.
- `src/compiler.js` owns the runtime documents the artifact carries. The foundation and each saga compile the same way.
- `src/saga-instance.js` owns the instance backup of a saga, in the layout of an engine instance export.
- `src/packaging/` owns the artifact: build, manifest and digests. The artifact is data; its consumer verifies it.
- `src/` imports only Node built-ins and files of this repository. Never import engine, server or client code.
- This repository never writes to MongoDB, the Object Layer, a server or a deployment.
- Content defines what exists and how it functions. Studio authors render and placement; never write them here.

## Release

- The package version is the content version. A released version never changes.
- `build` and `pack` build from committed content only.
- The engine reads the artifact of this checkout, or of the path `CYBERIA_CONTENT_ROOT` names.
- The deployment records the released artifact in `content-lock.json`.
